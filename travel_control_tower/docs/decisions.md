# 决策记录

这份文件只记已经定死的事情，避免每轮重新争论。

## 产品方向

- 产品是旅行规划控制塔，不是 OTA。
- 不做自动下单。
- 默认输出一套主方案，不平铺很多平行方案。
- 每天的餐食必须进入结果。
- 真实路程和缓冲时间必须分开展示。

## 工程方向

- 先做规划引擎，再做正式 Web 页面。
- 当前规划引擎使用 Python。
- 外部数据全部通过适配层接入。
- 输入和输出 schema 作为长期接口维护。
- 当前阶段的验收方式是本地 HTML / 本地 Web，而不是读代码。

## 当前范围

- v0 先打通：输入 -> 规划 -> 预览
- v0 不做：自动下单、OCR、截图导入、复杂协作
- v0 先以单场景模板验证，再扩展到更通用的目的地
